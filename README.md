# 적응형 코치

운동·식사·체중·체형을 기록하면, 근거 기반 규칙 엔진이 다음 운동 루틴과 식단을 다시 짜서 **제안 → 승인** 방식으로 바꿔 주는 개인용 앱.

> 의학적 진단·치료를 대신하지 않습니다. 통증·질환이 있으면 전문의와 상담하세요.

## 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 트레이너·영양사 관점 규칙 검토 (`docs/01-rule-review.md`, 로컬 전용) | 완료 (D1~D8 확정) |
| 2 | 데이터 모델·폴더 구조 (`docs/02-data-model.md`, 로컬 전용) | 완료 |
| 3 | 기록 + 운동 모드 + 타이머, 식단 탭(레시피), 웹 푸시 알림 | 완료 |
| 4 | 적응 엔진(운동 → 식단), 코치 화면, 테스트 | 완료 |
| 5 | 통계, 식품성분 DB·단백질/칼로리 진행 바, AI 메뉴 생성, 목표 설정 | **완료** |

### 3단계에서 되는 것
- **오늘**: 시간순 타임라인(수면·체중·끼니 체크), 오늘 운동 카드, 음주 가능 여부, 48시간 휴식 경고, 수면 부족 경고
- **운동 모드**: 워밍업(선택) → 종목별 세트 입력(큰 −/+ 버튼) → 휴식 타이머 자동 시작(60/90/120초, +15초) → 버티기 종목은 3초 준비 후 카운트다운 → 종목마다 난이도·통증(근육 뻐근함 / 관절 통증 / 위험 신호) → 지난 기록과 비교. 진행 중 세션은 새로고침해도 이어짐. 화면 꺼짐 방지.
- **유산소**: 종류 선택(2024 Compendium MET), 스톱워치·랩·일시정지, 끝나면 대화 테스트로 강도 기록
- **타이머**: 단독 휴식 타이머, 스톱워치(랩)
- **기록**: 체중·허리(주 평균), 수면, 음주(표준잔·kcal 자동 계산), 월간 둘레·사진(기기에만 저장), 냉장고 재료, 운동 기록
- **설정**: 신체 정보, 장비(가진 장비 안에서만 종목 선택), 일정, 소리·진동, JSON 백업/복원(사진 포함 선택), 초기화, 근거 출처 전체 보기
- 모든 목표치·경고 옆의 **ⓘ** → "내 기록"과 "근거(기관·연도·핵심 수치·원문 링크·원문 대조 여부)"

### 4단계: 코치 (적응 엔진)
- **주간 점검**: 매주 일요일 자동, 또는 코치 탭의 '지금 점검하기'. 결과는 "이번 주 변경 제안"으로 나오고, **승인해야** 프로그램 새 버전이 생긴다. 거절한 같은 제안은 4주 동안 다시 내지 않는다.
- **운동 진행** (`engine/progression.ts`): 2회 연속 모든 세트 목표 +1회 → 다음 목표는 최근 세션에서 가장 적게 한 세트 횟수(상한 12회까지) → 상한에서도 넘기면 사다리 다음 종목. 2회 연속 미달 유지, 3회 연속 미달 한 단계 내림. 관절·찌르는 통증은 한 단계 내림 + 전문의 안내. 다음 단계 장비가 없으면 장비 제안.
- **부위 균형** (`engine/balance.ts`): 최근 7일 부위별 세트(보조근 0.5세트). 우선 부위 주 5~10세트, 하체 주 4세트·2일 이상. 어깨 측면 종목이 없으면 밴드 제안 또는 레터럴 레이즈 추가, 수직 밀기(파이크 푸쉬업) 추가 제안.
- **유산소** (`engine/cardioReview.ts`): WHO 중강도 환산 분(고강도 2배)을 150분과 비교. 대화 테스트에서 2회 연속 '노래 가능'이면 자전거로 강도 올림.
- **식단** (`engine/bodyTrend.ts`): 주 평균 체중(주 3회 이상 측정)과 허리 추세로 ±150 kcal, 1,500 kcal 하한, 리컴포지션이면 그대로, 단백질은 체중 × 1.6~2.0 g 범위로.
- **근거가 없는 기준**은 코치 탭의 "정해 주세요"에서 답하면 사용자 결정값으로 저장되고(ⓘ에 표시), 그 값으로 다음 점검부터 제안한다.
- 에너지필요추정량(NASEM 2023)은 참고 표로만 보여준다. 활동 수준을 기록으로 정하는 방법은 원문 확인 전이다.

### 5단계
- **목표 설정**: 설정 → 목표에서 부위별 '우선/보통/유지'. 코치의 부위 균형 제안이 이 값을 따른다.
- **통계** (기록 → 통계): 체중(매일·주 평균), 허리, 어깨÷허리, 부위별 주간 세트, 유산소, 음주, 수면, 종목별 최고 기록, 같은 각도 사진 비교. 기간 4주/12주/전체, 모든 그래프에 '표' 보기.
- **식품성분**: `src/data/foods.ts` — 농촌진흥청 국가표준식품성분 DB 10.4 값(가식부 100 g당, 항목명·코드 기록). 우삼겹·그릭요거트·고형 카레는 같은 항목이 없어 가장 가까운 항목. 단위 무게(달걀 1개 등)는 공식 값을 찾지 못해 추정값이며, 밥 1공기 210 g만 공식 값.
- **진행 바**: 오늘 화면의 단백질·칼로리 = 끼니 체크(계획대로는 메뉴 재료로 계산, 다른 거는 입력값) + 술. 식단 탭에 메뉴별·하루 합계 영양.
- **AI 메뉴 생성** (선택): 설정에 Claude API 키를 넣으면 식단 탭에서 이번 주 저녁 메뉴를 만든다. 모델 `claude-opus-5-5`, 안전 분류기 거절 시 서버 대체 모델(`fallbacks: "default"`). AI는 식재료 목록의 id와 g만 고르고, 칼로리·단백질은 앱이 다시 계산해 목표와 비교한다. 키는 기기에만 저장되고 백업에서 빠진다. 장보기 목록 = 필요량 − 냉장고 재료.

### 웹 푸시 알림
- 설정 → 휴대폰 알림에서 허용 → 등록 코드를 GitHub 비밀값 `PUSH_SUBSCRIPTION`에 넣는다(여러 기기는 JSON 배열).
- `.github/workflows/push.yml`이 매일 11:00(수면 기록), 월~토 14:30(운동)에 보낸다. 시각은 cron(UTC)으로 바꾼다. GitHub 예약 실행이라 늦을 수 있다.
- 서명 키는 `VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY` 비밀값. 앱의 공개키는 `src/lib/push.ts`.
- 공개 저장소는 60일 활동이 없으면 예약 실행이 꺼져서 `keepalive.yml`이 매달 빈 커밋을 올린다.

## 실행 방법 (맥)

Node.js 24 이상이 필요합니다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 을 엽니다. 같은 와이파이의 아이폰에서는 터미널에 표시되는 `Network:` 주소로 화면을 볼 수 있지만, **홈 화면 설치·오프라인은 HTTPS 주소에서만** 됩니다(아래 참고).

```bash
npm test
```

```bash
npm run build
```

`dist/` 폴더가 배포할 결과물입니다.

## 배포 (GitHub Pages)

`main` 브랜치에 푸시하면 GitHub Actions(`.github/workflows/deploy.yml`)가 테스트 → 빌드 → Pages 배포를 합니다. 앱은 해시 라우팅과 상대 경로로 빌드되어 `https://아이디.github.io/coach/` 같은 하위 경로에서 동작합니다. 새 버전이 배포되면 앱을 다시 열 때 자동으로 바뀝니다.

배포되는 것은 앱 코드뿐입니다. 키·체중·출생연도·생활 시간·음주 목표는 코드에 넣지 않고 **첫 실행 화면에서 입력해 기기에만** 저장합니다. 개인 정보가 담긴 `docs/`는 `.gitignore`로 저장소에서 뺐습니다.

## 아이폰·맥 홈 화면 설치 (PWA)

1. 아이폰 **Safari**로 배포 주소를 엽니다 (Chrome 앱에서는 홈 화면 앱으로 설치되지 않습니다).
2. 공유 버튼 → **홈 화면에 추가** → 추가.
3. 홈 화면의 '코치' 아이콘으로 엽니다. 첫 실행 화면에서 정보를 입력하거나, 다른 기기의 백업 파일로 시작합니다.
4. 맥 Safari는 파일 → **Dock에 추가**, Chrome은 주소창의 설치 아이콘.

**기록은 각 기기의 IndexedDB에만** 저장됩니다. Safari 탭과 홈 화면 앱도 저장소가 따로이니, 홈 화면 앱으로만 쓰세요.

## 한계 (알고 있는 것)

| 항목 | 내용 |
|---|---|
| 기기 간 동기화 없음 | 서버가 없어서 아이폰과 맥의 데이터는 따로입니다. Safari 탭과 홈 화면 앱도 저장소가 따로입니다. 주 기기를 하나 정하고, 다른 기기로는 설정 → 내보내기/가져오기로 옮기세요. |
| 진동 | iOS Safari는 진동 API를 지원하지 않습니다. 휴식 종료는 소리와 화면으로 알립니다. |
| 소리 | iOS는 사용자가 한 번 탭한 뒤에만 소리를 낼 수 있어서, 운동 시작 버튼에서 소리를 켭니다. 화면이 꺼지거나 다른 앱으로 가면 소리가 나지 않을 수 있습니다. |
| 정시 알림 | 웹 푸시(GitHub Actions 예약 실행)로 보냅니다. 예약 실행은 몇 분~수십 분 늦을 수 있고, 등록 코드가 바뀌면(앱 재설치 등) 다시 등록해야 합니다. |
| 화면 꺼짐 방지 | Wake Lock API를 씁니다. 홈 화면 앱에서는 최신 iOS에서만 동작합니다. 안 되면 운동 중에는 자동 잠금을 꺼 두세요. |
| 타이머 정확도 | 화면이 꺼져 있는 동안 JS가 멈춥니다. 타이머는 시작 시각 기준으로 계산하므로 돌아오면 정확한 시간으로 이어집니다. |
| 저장 공간 | 사진은 긴 변 1600px JPEG로 줄여 저장합니다. 브라우저가 데이터를 지우지 않도록 영구 저장을 요청하지만, 보장되지는 않으니 정기 백업을 권장합니다. |
| 단백질·칼로리 진행 바 | 식품성분 DB(농촌진흥청)를 붙이는 4단계부터 표시됩니다. |

## 구조

```
src/
  engine/   순수 함수 규칙 엔진 + Vitest (React·DB·현재 시각 의존 없음)
  data/     evidence.ts(근거) · rules.ts(엔진 상수 = 값 + 근거) · exercises.ts(종목·사다리)
            initialProgram.ts(시작 프로그램·기본 설정) · drinks.ts(주종·유산소 MET)
  db/       Dexie(IndexedDB) 스키마, 백업/복원
  features/ today · workout · timer · records · settings
  components/ 공용 UI, Why(ⓘ)
  lib/      소리·진동·화면 꺼짐 방지, 시간, 이미지 축소
```

규칙 원칙: 엔진이 쓰는 숫자는 모두 `rules.ts`에 `{ value, basis }`로만 존재합니다. 근거가 없으면 `needs-evidence`(값 없음, 엔진이 쓰지 않음)이거나, 사용자가 정한 값이면 `user-decision`으로 표시됩니다. `src/data/data.test.ts`가 이 규칙(모든 근거 참조가 존재하는지, 값이 비어 있는 규칙은 근거 확인 필요뿐인지)을 검사합니다.

## 근거 출처

전체 목록과 원문 대조 결과는 `src/data/evidence.ts`와 앱의 설정 → 근거 출처에 있습니다. 주요 출처:

- 운동: ACSM 2009 진행 모델(Ratamess 등), ACSM 2011(Garber 등), WHO 2020 신체활동 가이드라인, 2024 Adult Compendium of Physical Activities, Campos 등 2020(J Hum Kinet), Schoenfeld 2017, Pelland 2025, Spiering 2021, Bickel 2011, Vispute 2011, Ismail 2012, Barakat 2020, CDC 대화 테스트
- 영양: ISSN 단백질·영양 타이밍 2017, 2020 한국인 영양소 섭취기준, IOM 2005 / NASEM 2023 에너지 공식, Ruiz-Castellano 2021, 대한비만학회 2022, NHLBI 1998, Iraki 2019, NICE NG246, Turicchi 2020, Steinberg 2013, Hall 2011, 농촌진흥청 국가표준식품성분 DB
- 음주·수면: Lee 등 2019(한국형 적정 음주), 질병관리청 고위험음주 지표, Parr 2014, FAO 2003, AASM·SRS 2015, Nedeltcheva 2010
